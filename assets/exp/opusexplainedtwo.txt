## 🎯 PROJECT MISSION

OpusHunter is a "set it and forget it" autonomous job application engine. A user creates an account, fills in their career profile and preferences, uploads their CV and certifications, and the system automatically:

1. Scrapes matching job listings from multiple sources in parallel (JSearch + Adzuna, with a flexible scraper architecture that can add new sources without refactoring)
2. Deduplicates and normalizes listings using deterministic hashing
3. Extracts the user's full career narrative from uploaded documents using AI
4. Generates tailored, company-named, role-specific, 4–5 paragraph cover letters with quantified impact for each job using Google Gemini
5. Presents a fluid, swipeable triage UI for the user to review
6. Dispatches applications (cover letter + hard links) with one tap

The experience must feel **exceptional** — smooth, fast, beautiful, and reliable on every platform.

## 📁 DELIVERABLE 4 — EDGE FUNCTION ORCHESTRATION LAYER

Implement all Supabase Edge Functions as complete, production-ready Deno TypeScript files.

### `supabase/functions/_shared/keyResolver.ts`
The **triple-tier API key resolver** used by all Edge Functions:
1. **Tier 1:** Check `user_api_keys` for the calling user's own key for the requested provider
2. **Tier 2:** If not found or invalid, fall back to `system_api_keys` ordered by `priority_order ASC`, cycling through on `429` responses
3. **Tier 3:** If all system keys exhausted, return a structured error with `{ error: 'quota_exhausted', retryAfter: ... }`
- All key lookups use Service-Role client — never exposed to client
- Log every key usage to `api_key_usage_logs`

### `supabase/functions/scrape-jobs/index.ts`
**Multi-source parallel job scraper:**
- Accepts: `{ userId, searchParams: { keywords, workTypes, countries, cities, radiusKm, experienceLevel, datePosted, page } }`
- Enforces 24-hour rate limit: check `scrape_rate_limits` — if `last_scrape_at` is within 24 hours for `member` role, return `{ error: 'rate_limited', nextAvailableAt: ... }`. Premium users with their own API keys bypass this limit.
- Fires JSearch and Adzuna requests **in parallel** using `Promise.allSettled`
- **JSearch adapter:** Normalizes RapidAPI JSearch response to `JobListing` schema. Passes `country: 'SE'` and Swedish city names correctly. Handles `429` via keyResolver cycling.
- **Adzuna adapter:** Uses the correct regional endpoint (`/se/jobs/search` for Sweden, `/gb/jobs/search` for UK, etc.). Normalizes Adzuna response to `JobListing` schema. Handles `429` via keyResolver cycling.
- **Flexible scraper registry pattern:** Scrapers are registered in an array `const scrapers: ScraperAdapter[] = [jsearchAdapter, adzunaAdapter]`. Adding a new source requires only creating a new adapter file and adding it to this array — zero changes to orchestration logic.
- **Deduplication:** After merging results, compute `dedup_hash = sha256(normalize(company + title + location))`. If hash exists in `job_listings` for this user, skip. Keep the richer record (more fields populated) when cross-source duplicates are detected.
- Upsert up to 30 normalized listings per scrape batch into `job_listings`
- Return paginated results with metadata: `{ listings: JobListing[], total: number, page: number, sources: { jsearch: number, adzuna: number } }`

**Sweden-specific handling (non-negotiable):**
- GeoDB Cities must resolve: Stockholm, Gothenburg (Göteborg), Malmö, Uppsala, Västerås, Örebro, Linköping, Helsingborg, Jönköping, Norrköping
- Adzuna Sweden endpoint: `https://api.adzuna.com/v1/api/jobs/se/search/1`
- JSearch: pass `location=Stockholm, Sweden` and `country=SE` in query params
- Radius filtering applied post-fetch using haversine distance calculation

### `supabase/functions/extract-context/index.ts`
**AI-powered career context extraction:**
- Triggered after document upload to Supabase Storage
- Downloads the document binary from Storage using Service-Role client
- For PDF: extracts text using a Deno-compatible PDF parser
- For DOCX: extracts text using XML parsing
- Sends extracted text to Gemini with a structured prompt requesting JSON output:
  ```json
  {
    "extracted_skills": ["TypeScript", "React", "Java", ...],
    "extracted_experience": [{ "company": "...", "role": "...", "duration": "...", "achievements": ["..."] }],
    "extracted_education": [{ "institution": "...", "degree": "...", "year": "..." }],
    "extracted_certifications": [{ "name": "...", "issuer": "...", "date": "..." }],
    "career_summary": "...",
    "key_achievements": ["Reduced API latency by 40%", "Led team of 6 engineers", ...]
  }
  ```
- Upserts result into `user_context` table
- Uses keyResolver for Gemini API key

### `supabase/functions/generate-cover-letter/index.ts`
**Advanced AI cover letter generation:**
- Accepts: `{ userId, jobListingId }`
- Fetches from Supabase: `user_context`, `profiles`, and the full `job_listings` record for `jobListingId`
- Constructs a rich, structured prompt that includes:
  - User's full name (from `profiles.first_name + last_name`)
  - Career summary, key achievements, extracted skills, certifications
  - Target job title, **exact company name**, location, work type
  - Full job description text
  - Instruction: "Write a professional, concise 4–5 paragraph cover letter. Address it to [Company Name]. Open with a strong hook referencing the specific role. Paragraph 2: match the candidate's top 3 relevant skills/achievements to the job requirements with quantified impact where available. Paragraph 3: demonstrate knowledge of the company and why this specific role. Paragraph 4: certifications and technical depth relevant to this role. Closing: confident call to action. No filler phrases. No generic statements. Every sentence must earn its place."
  - Tone: professional, direct, confident — not sycophantic
- Sends prompt to Gemini Flash, parses response
- Stores result in `cover_letters` table with `company_name`, `role_title`, `content`, `tokens_used`, `generation_duration_ms`
- Returns the complete cover letter record
- Uses keyResolver for Gemini API key

### `supabase/functions/geo-autocomplete/index.ts`
**GeoDB Cities proxy with Swedish priority:**
- Accepts: `{ query: string, countryCode?: string }`
- Proxies to GeoDB Cities API with rate-limit buffering
- When `countryCode = 'SE'` or query matches Swedish city patterns, prioritizes Swedish results
- Returns: `{ cities: [{ name, country, countryCode, latitude, longitude }] }`

## 📁 DELIVERABLE 7 — RATE LIMITING & BYOK ARCHITECTURE

### Scrape Rate Limiting Rules:
- **Member role:** Can trigger the scrape engine **once every 24 hours**. Enforced in the `scrape-jobs` Edge Function by checking `scrape_rate_limits.last_scrape_at`. Returns a clear error with `nextAvailableAt` timestamp if limit exceeded.
- **Premium role with own API keys:** No rate limit enforced — their keys, their quota.
- **Premium role without own API keys:** Same 24-hour limit as member (uses system keys).
- The UI must display the rate limit status clearly: "Next scrape available in X hours" with a countdown.

### API Key Cascade (enforced in `keyResolver.ts`):
```
1. Check user_api_keys for this user + provider → use if exists and active
2. If not found → query system_api_keys ORDER BY priority_order ASC
3. Try each system key in order → on 429, mark as temporarily throttled, try next
4. If all exhausted → return { error: 'quota_exhausted' }
5. Log every attempt to api_key_usage_logs
```
